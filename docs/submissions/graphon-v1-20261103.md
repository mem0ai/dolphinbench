## Configuration

- **Agent:** `gpt-5.6-luna`, reasoning effort high, through our own harness
  on the DolphinBench runner. The system prompt is the release's Hermes
  identity prompt plus memory prompts. Those prompts tell the agent to search
  memory with the `recall` tool, and the first turn must call it. The full
  prompt is in `tests.json`.
- **Memory:** Graphon Engine. The runner sends each history message in
  order, and the harness stores it in Graphon Engine. No agent model runs at
  ingest, so the ingest records show zero tokens. `recall` asks Graphon Engine
  a question and returns its answer with the text of the sources it cites.
- **Memory isolation:** tests read memory with a key that cannot write, so a
  test cannot change memory. Before the tests, we checked the stored memory
  against the ingest checkpoints.
- **Judge:** `gpt-5.6-sol` at medium effort, sent to the OpenAI API instead
  of Azure. The model, settings and prompts are the release's. The export
  passes judge messages through the release's `clean_message`, which removes
  the `refusal` and `annotations` fields that OpenAI's replies add.

## Website validation

On the receipt, the run shows `queued` with 3 of 3 attempts used, and the
message "Validation could not finish. The run remains pending for retry."
The stored file's SHA-256 matches the ZIP above. The run was not rejected,
but it does not retry by itself.

What we checked:

- `harness.submission.validate` passes on Linux under the limits in
  `api/submission_validator.py`: 2 GiB `RLIMIT_AS`, with network and
  subprocess calls blocked. It uses about 5 s of CPU and peaks at 1.38 GB RSS.
- Most of that memory comes from loading `release.json` (about 340 MB). The
  ZIP is about 32 MB when unpacked.
- `vercel.json` sets `maxDuration` for `api/submission_validator.py` but no
  memory size. We think the function process plus a validator child of about
  1.4 GB may exceed the function's memory, so the child is killed. If so,
  other submissions can fail the same way.

We would be glad if the maintainers could re-queue the website submission, or
list this run from the evidence here.
